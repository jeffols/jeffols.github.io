The thesis

Several sources trace this progression independently. Read in order, it is a curriculum rather than a pile of links.

prompt engineering → context engineering → loop engineering → graph engineering

Progressive disclosure is the mechanism that makes it affordable. Schema constrained state is the memory and decision layer. And what separates a graph from an expensive loop is one rule.

A graph is a loop with something that can contradict it.

Phase 4 is the phase most people skip. The agent memory field has converged on schema constrained knowledge graphs with temporal facts, which is ontology engineering, a discipline with thirty years of prior art behind it. Reading the foundations makes the rest stop looking like novelty.

That overlap is not an observation original to this page. Intentional Arrangement has been publishing on semantic infrastructure and what agentic systems need since mid 2025, including a three part series on AI autonomy and a piece from January 2026 titled Ontologies, Context Graphs, and Semantic Layers, What AI Actually Needs. Phase 4 collects that work. What this plan adds is the sequence, and the readings from the other side of the gap.

0.01Free

Forget Loop Engineering. It's all about Graph Engineering Now

The AI Corner · 2026-09-02

Verification anchors. A loop optimises the one number it can see, by any route available, including routes nobody would have approved. Multi agent verification is consensus theater, since identical weights share identical blind spots, and parallel verification costs 10 to 100 percent more rather than less. The rule that survives is that on every critical path at least one node must be non probabilistic.

The distinction this phase turns on

Calibrated is not deterministic. A decision model trained against outcomes rather than rater preference should have confidence numbers that track real accuracy, which is a genuine property most model confidence scores lack. It is still a model making a probabilistic call.

So a typed decision node is a better behaved judge, not the non probabilistic anchor that 0.01 argues every critical path needs. A compiler is that. A schema validator is that. A decision model sits closer to independent than a second frontier instance does, because it is a different architecture trained on different data, so the correlated blind spot problem shrinks. It does not disappear.

Where does the calibration come from, and what happens to it when the distribution shifts? Carry that question into anything in this space, including whatever replaces the current tooling.

Four things to build

Reading without building turns eighteen hours into industry awareness. Each of these is small and traceable to a specific reading.

01

Route the skills directory

Convert a flat skills folder into a harness tree. A root descriptor, routing files named for their own subdirectory so the agent reads summaries before descending, and leaf markers where exploration should stop and a tailored skill should take over. Then add reverse reference lookup so a single high level edit cascades to every routing document that mentions the target.

from 2.02, validated against 5.13
02

Write the memory schema before the memory code

Three or four entity types. Three or four edge types, each with source and target constrained so invalid relationships are unrepresentable rather than merely unlikely. Temporal facts kept separate so what was true never silently serves as what is true. Expand only when retrieval actually fails, not in anticipation.

from 3.02, grounded by 4.10 and 4.12
03

Put one non probabilistic node on every critical path

A compiler, a type checker, a schema validator, something with zero error correlation to the model. Majority voting several model instances is not verification, because they share weights, training data and blind spots. Audit anywhere a fan out to multiple agents currently gets treated as a check.

from 0.01, installed via 5.03
04

Measure what loads before reasoning starts

Count the tokens spent on tool definitions and always on context before the model does any work. The comparison worth making is that metadata only discovery runs around eighty tokens per skill, while a large tool roster can cost fifty thousand before the first thought.

from 1.04, payoff documented in 5.10
